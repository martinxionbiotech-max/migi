# Resources: Documentation, Certificates and Validation Records

**Quick Answer** — This section is being built as a structured document library. Until it is complete, current documents are supplied on request, and this page exists so that buyers know exactly what to ask for, what each document contains, and what is not yet available.

## What belongs in a document library

| Document | What it contains | Who needs it |
|---|---|---|
| IFU (instructions for use) | Intended use, specimen, procedure, performance, limitations | Every user; registration dossiers |
| CoA (certificate of analysis) | Batch-specific test results against specification | Quality review, release testing |
| Validation summary | Analytical and clinical performance, with methods | Distributors, tender evaluation |
| TDS (technical data sheet) | Specifications in a comparable format | Procurement, technical evaluation |
| QMS certificates | ISO 13485 / ISO 9001, with scope | Registration, supplier qualification |
| SDS | Handling and transport safety information | Logistics, customs, workplace safety |

## How to request

Requests are handled by technical support. To make the response useful, include:

1. Product name and catalogue number.
2. The reagent lot, if the request concerns a specific batch.
3. The document type required (IFU, CoA, validation summary, certificate).
4. The intended purpose — registration, tender, internal qualification — because the required format differs.

## Version control matters more than the document

An IFU without a version number and effective date is not usable in a registration dossier, and it is dangerous in practice: procedures and performance claims change between revisions. When you receive a document, check:

- The version identifier and effective date.
- Whether it applies to the reagent lot you hold.
- Whether the performance figures match those published on the technical pages of this site.

If they do not match, treat the mismatch as information rather than as noise — it may indicate an older document in circulation.

## Why this page lists gaps

Most vendor resource pages present a complete-looking set of icons. In practice, document availability varies by product, by market and by product generation, and discovering a gap during a tender submission is expensive for the buyer.

## The Author's Take

**Position.** A document library is the highest-return page on a diagnostic site, and the honest version — with visible gaps — outperforms the complete-looking version that cannot be defended.

**Reasoning.** Registration and tender processes are document-driven: a distributor's timeline is set by how long it takes to assemble a dossier, and every missing certificate is a week. A vendor who publishes what exists, what does not, and how to request it removes the worst part of that process — the uncertainty. The temptation is to present a full set of icons because competitors do; but a buyer who clicks four empty icons concludes the vendor is disorganised, while a buyer who sees an accurate status table concludes the vendor knows its own documentation. The second impression is worth more, and it is the only one that survives contact with an actual request.
